# 二、主站（nano-blog）

## 2.1 目录结构

```
D:\blog\nano-blog\
├── build.py              生成器（唯一核心脚本，配置就在文件顶部）
├── serve.py              本地预览服务器
├── requirements.txt      markdown-it-py + Pygments
├── content\              每篇文章一个 .md（下划线开头的不当文章，如 _about.md）
│   └── _about.md         「关于我」页
├── theme\                主题资源
│   ├── styles.css        首页样式
│   ├── articles.css      内页样式（Pygments 代码配色由 build.py 自动追加）
│   ├── hero.webp         首页头像
│   ├── favicon.svg
│   └── CNAME             orangeheart.top（部署时写入产物）
├── tools\import_note.py  从 Obsidian 导入笔记
└── public\               构建产物（已 gitignore，不要手改）
```

## 2.2 写一篇新文章

在 `content\` 下新建 `my-note.md`：

```markdown
---
title: 标题
date: 2026-09-15
tags: [工作记录, 笔记]
summary: 可选，不写就从正文首段自动摘
slug: my-note          # 可选，默认取文件名
---

正文（Markdown，支持表格、代码高亮、单换行也换行）。
```

> 文件名以 `YYYY-MM-DD` 开头时日期会自动从文件名取。

### 从 Obsidian 导入（推荐）

```powershell
cd D:\blog\nano-blog
python tools\import_note.py "D:\Obsidian\Qtech\...\2026-09-15.md" `
  --title "标题" --tags 工作记录,笔记 --slug my-note
```

脚本会自动补 front matter、去掉与标题重复的一级标题。

## 2.3 本地预览

```powershell
cd D:\blog\nano-blog
python build.py          # 生成到 public\
python serve.py          # 打开 http://127.0.0.1:8000/
```

改完 Markdown / CSS 后重新 `python build.py` 即可（本地预览禁用缓存，刷新就是最新）。

## 2.4 发布上线

```powershell
cd D:\blog\nano-blog
git add -A
git commit -m "post: 标题"
git push

# 立即发布（不执行的话每天 06:00 自动同步）
gh workflow run publish.yml -R TiAmo-chen/TiAmo-chen.github.io
```

看看有没有发布成功：

```powershell
gh run list -R TiAmo-chen/TiAmo-chen.github.io -L 3
gh run view <运行ID> -R TiAmo-chen/TiAmo-chen.github.io --log
```

## 2.5 想改哪里 → 改哪个文件

| 想改的东西 | 去哪改 |
|---|---|
| 站点名 / 副标题 / 描述 | `build.py` 顶部 `SITE["title"]` / `["tagline"]` / `["description"]` |
| 首页大字标语 | `SITE["home_headline"]` |
| 首页「最近在做」时间线 | `build.py` 的 `ACTIVITY` |
| 首页社交图标 | `build.py` 的 `SOCIALS`（留空则不显示） |
| 首页头像 | 换 `theme\hero.webp`，再改 `SITE["hero"]` 与 `SITE["hero_size"]` |
| 首页「最近更新」条数 | `SITE["recent"]`（现在 10 条） |
| 顶部导航项 | `build.py` 的 `NAV` 列表 |
| 首页版式 / 配色 / 动画 | `theme\styles.css` |
| 文章页排版 / 代码配色 | `theme\articles.css`（文件末尾的 Pygments 部分由 `build.py` 生成，别手改） |
| 页脚文字 | `build.py` 里 `footer()` 与 `page_home()` 的 `<footer class="footer">` |
| 「关于我」页 | `content\_about.md` |
| 域名 | `SITE["base_url"]`（影响 sitemap / RSS / og:url） |

## 2.6 首页配图规格

- 文件名放 `theme\` 下（`.webp` / `.png` / `.jpg` / `.svg` 都会被拷进产物）
- 建议 1:1 或竖版半身像，宽度 ≥ 760px，体积 ≤ 300 KB
- 改完在 `build.py` 里同步两行：

```python
"hero": "/hero.webp",
"hero_size": (760, 819),      # 写 <img width height> 防抖动
```

- 深色模式下透明背景的图最自然（现有头像就是透明底）

# 三、数字花园（Quartz）

## 3.1 目录结构

```
D:\code\blogs\1\Quartz\
├── content\              ← 你的笔记都放这里（Obsidian 可直接打开这个文件夹）
├── quartz.config.ts      ← 站点配置（标题、域名、语言、主题色、插件列表）
├── quartz.layout.ts      ← 布局（左侧文件树、右侧大纲、搜索等组件的位置）
├── quartz\               ← Quartz 本体（git 子模块，一般不用动）
└── quartz.7z / 其他      ← 历史遗留，可忽略
```

## 3.2 发布规则（很重要）

Quartz 装的是 **ExplicitPublish** 模式：**只有 front matter 里写了 `publish: true` 的笔记才会出现在网站上**。

```markdown
---
title: "笔记标题"
publish: true        # ← 必须显式写 true 才会发布
draft: false         # draft: true 则永远不发布
tags: [C++, 笔记]
---
```

- 不想发布：把 `publish` 改成 `false`，或把 `draft` 改成 `true`
- 新增笔记默认不会出现，别以为是没部署成功

## 3.3 写笔记 + 发布

```powershell
cd D:\code\blogs\1\Quartz
# 用 Obsidian 打开 content\ 文件夹写笔记，或直接编辑 md 文件
git add -A
git commit -m "note: 新增 xxx"
git push            # push 到 main 后 GitHub Actions 自动构建并部署
```

查看部署：

```powershell
gh run list -R TiAmo-chen/Quartz -L 3
```

## 3.4 本地预览

Quartz 的配置写在仓库根目录，但构建要在子模块里跑，所以要先把配置拷进去（CI 里也是这么做的）：

```powershell
cd D:\code\blogs\1\Quartz
Copy-Item quartz.config.ts,quartz.layout.ts quartz\ -Force

cd quartz
node quartz\bootstrap-cli.mjs build -d ..\content --serve --concurrency 20
# 打开 http://localhost:8080/
```

首次使用需先装依赖：`cd quartz; npm i`（需要 Node.js ≥ 22）。

## 3.5 想改哪里 → 改哪个文件

| 想改的东西 | 去哪改 |
|---|---|
| 站点名 / 后缀 | `quartz.config.ts` 的 `pageTitle` / `pageTitleSuffix` |
| 语言（界面文案） | `locale`（现在是 `zh-CN`） |
| 域名（影响 RSS/sitemap） | `baseUrl`（现在是 `note.orangeheart.top`，不要带 `https://`） |
| 忽略哪些文件 | `ignorePatterns` |
| 配色 | `theme.colors` 的 `lightMode` / `darkMode` |
| 字体 | `theme.typography` |
| 是否每篇都发布 | `plugins.filters` 里的 `ExplicitPublish` / `RemoveDrafts` |
| 左侧文件树、搜索、图谱等组件 | `quartz.layout.ts` |
| 单篇是否公开 | 那篇笔记的 front matter `publish` / `draft` |

# 四、域名与部署链路

| 域名 | DNS | 托管 |
|---|---|---|
| `orangeheart.top` | Cloudflare CNAME → `tiamo-chen.github.io`（**已代理/橙云**） | GitHub Pages 用户站 `TiAmo-chen.github.io` |
| `note.orangeheart.top` | Cloudflare CNAME → `tiamo-chen.github.io`（**仅 DNS/灰云**） | GitHub Pages 项目站 `TiAmo-chen/Quartz` |

关于 `note` 那条灰色云的提示：Cloudflare 会提示"此记录暴露了源站 IP"，**可以忽略** —— 源站是 GitHub Pages 的公共 CDN，不是私有服务器；而且 GitHub 需要非代理状态才能签发/续期证书。想开橙云也行，但要把 CF 的 SSL/TLS 模式设为 **Full (strict)**。

# 五、常见问题排查

**Q1：我改了东西，网页上没变化？**

1. 先本地构建看对不对：`python build.py` → `python serve.py`
2. 再确认有没有发布：`gh run list -R TiAmo-chen/TiAmo-chen.github.io -L 3`
3. 最后考虑缓存：HTML 被 Cloudflare 加了 `max-age=600`，**约 10 分钟自动刷新**；想立刻看按 `Ctrl+Shift+R`
   （CSS 和图片现在带内容哈希版本号 `?v=xxxxxxxx`，改了就必然重新拉取，不用管缓存）

**Q2：主站首页头像/样式想换回旧的？**

所有历史版本都在 git 里：

```powershell
cd D:\blog\nano-blog
git log --oneline -- theme/hero.webp    # 找到想回到的那个提交
git checkout <提交号> -- theme/hero.webp
```

**Q3：想把主站整体退回 Hexo？**

线上产物仓库里存了切换前的完整快照：

```powershell
git clone https://github.com/TiAmo-chen/TiAmo-chen.github.io.git
cd TiAmo-chen.github.io
git checkout hexo-final          # Hexo 最后一版
git push origin hexo-final:master --force
```
（或者干脆把 Pages 源改回那个分支）

**Q4：Quartz 新笔记没上线？**

99% 是没写 `publish: true`。检查 front matter，然后 `git push` 一次。

**Q5：Quartz 本地起不来？**

- Node 版本：`node -v` 必须 ≥ 22
- 子模块没拉全：`git submodule update --init --recursive`
- 忘了拷配置进子模块：见 3.4
- 依赖没装：`cd quartz; npm i`

**Q6：想让 Cloudflare 清缓存？**

CF 控制台 → 你的域名 → **Caching** → **Configuration** → **Purge Everything**（或按 URL 精确清除）。

**Q7：怎么看发布用的工作流？**

主站的发布逻辑在 `TiAmo-chen/TiAmo-chen.github.io` 仓库的 `.github/workflows/publish.yml`：它会检出公开的 `nano-blog` 源码，用 Python 构建，然后把产物推到本仓库 `master`。
